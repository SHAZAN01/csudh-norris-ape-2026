\begin{abstract}
Large language models (LLMs) can post-edit neural machine translation (NMT) drafts, but an editor that repairs errors can also change names, numbers, or relations that the draft already rendered correctly. We evaluate this trade-off for English--Tagalog and English--Spanish in both directions on the held-out FLORES+ devtest partition (1{,}012 sentences per direction). A sentence-split NLLB-200 3.3B system supplies the draft; Llama 3 8B Instruct and GPT-4o Mini edit it under three prompting strategies: zero-shot, one retrieved development exemplar, and a single-call reason-then-edit format. All prompts, output contracts, and analyses were frozen on development data before the test partition was opened, and every planned output, including contract failures that fall back to the baseline, is evaluated. \pending{two to three sentences with the main held-out findings for RQ1--RQ4: largest/smallest COMET changes vs.\ the baseline with Holm-adjusted significance, strategy contrasts, protect-pool over-editing rates, reason-then-edit failure rates}. The results show that average quality, preservation of strong drafts, and output validity must be measured separately when deciding whether to deploy an LLM post-editor.
\end{abstract}
